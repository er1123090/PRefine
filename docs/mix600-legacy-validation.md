# mix600 Legacy Validation Warnings

The 2,638-instance generation contract is reproducible, but generation parity does not mean every GT is representable by the schema supplied to the model. These warnings are frozen in `tests/fixtures/dataset/mix600_legacy_validation.json` and regenerated by `tests/dataset/test_mix600_legacy_validation.py`.

## Schema-missing GT slots

| Scenario | Instances with at least one missing slot |
| --- | ---: |
| singleturn easy / medium / hard | 39 / 12 / 27 |
| multiturn easy / medium / hard | 63 / 129 / 193 |
| total | 463 |

The single-turn schema omits `number_of_seats`. The multi-turn schema omits GT base slots encountered in this baseline: `city`, `departure_date`, `destination`, and `pickup_time`. These 463 instances can therefore ask the model to predict an argument that its supplied tool schema does not declare. The regression test reports this condition; it does not silently remove or rewrite the legacy GT.

## Preference coverage and merge safety

- 123 source examples contain at least one preference group supported by the frozen `pref_group.json`.
- 477 source examples contain only `prefers_star` or `eco`, which the frozen medium/hard rules do not support, so they produce no medium/hard instances.
- All 25 multi-turn query templates have zero overlap between their base API-call slots and target preference slots. The current base-plus-preference merge therefore has no overwrite collision on these templates.

The legacy hard builder gathers candidate domains in a Python set, and the medium builder also materializes rule values through sets. Their iteration order can change with `PYTHONHASHSEED`, so positional `example_id_sub` values must not be treated as stable semantic identities. The main contract hashes normalized `(example_id, query, ground_truth)` multisets instead.

Run both gates with:

```bash
python -m unittest \
  tests.dataset.test_mix600_legacy_contract \
  tests.dataset.test_mix600_legacy_validation -v
```
